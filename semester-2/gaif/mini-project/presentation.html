Business Problem

The AML investigator's dilemma

Under HKMA AML/CFT guidelines and FATF Recommendations, banks must investigate alerts quickly while maintaining accuracy, auditability, and regulatory defensibility.

Pain Point 1

Alert overload

Transaction-monitoring systems generate thousands of alerts monthly. Analysts manually review transaction history, KYC files, prior alerts, and policy rules — with false-positive rates often exceeding 90%.

Pain Point 2

Hidden connections

Risk indicators are spread across customer systems, account data, counterparties, case histories, and unstructured investigation notes across multiple platforms.

Pain Point 3

Documentation burden

Analysts spend 40–60% of investigation time summarizing evidence and drafting case notes, reducing time for deeper analysis and professional judgment.

The core problem is not detection — it is helping analysts assemble evidence, understand context, and document decisions consistently under time pressure.

03 / 14
Proposed GenAI Solution

An intelligent AML investigation copilot

The system assists analysts with repetitive, evidence-heavy tasks while leaving final decisions under human control.

What the copilot does

  • Summarizes new AML alerts into a standard structure
  • Retrieves relevant internal policies and similar historical cases via RAG
  • Extracts entities: customers, accounts, counterparties
  • Drafts neutral, factual case notes with source citations
  • Flags confidence levels and data gaps

What the copilot does NOT do

  • Automatically close or escalate cases
  • Independently file Suspicious Transaction Reports
  • Make customer-exit or sanctions decisions
  • Access external internet data for confidential analysis
  • Replace professional AML judgment or accountability

Positioning: a controlled decision-support copilot — not an autonomous AML decision engine.

User Workflow

How an analyst uses the copilot

The design integrates into the existing AML workflow — it augments, not replaces.

1

Alert intake

New alert arrives from the transaction-monitoring system.

2

Evidence retrieval

RAG retrieves alert data, KYC profile, transactions, policies, and prior cases.

3

AI summary

LLM generates structured, source-grounded alert summary with confidence flags.

4

Graph linking

Entities and relationships are extracted and added to the knowledge graph.

5

Human review

Analyst verifies evidence, edits draft, applies professional judgment, approves.

6

Audit capture

All prompts, outputs, sources, edits, and approvals are logged.

Human-in-the-loop at every decision point. The AI accelerates evidence assembly — humans remain accountable.

Model Selection & Deployment

Why private deployment — and which model?

For AML investigations involving sensitive customer data, model deployment strategy is a critical architectural decision.

Option A: Private Cloud LLM

  • Examples: Azure OpenAI private endpoint, on-premise Llama
  • Pros: Better data control, access management, data residency alignment
  • Cons: Higher infrastructure cost, requires MLOps capability
  • Verdict: Recommended for production AML use

Option B: Public API

  • Examples: External LLM API services
  • Pros: Easy setup, low upfront cost, latest model capabilities
  • Cons: Data leaves bank perimeter, regulatory risk, vendor lock-in
  • Verdict: Use only for non-sensitive prototyping

Recommendation: Use a private cloud or on-premise LLM setup to satisfy data governance and security requirements.

Prompt Engineering

Prompts designed for factual, auditable output

The system prompt constrains the model to use only approved evidence and avoid unsupported conclusions.

System Prompt: AML Alert Summary

You are an AML investigation assistant for [Bank Name]. Summarize the provided alert data.

RULES:
1. Use ONLY the provided alert, KYC, transaction, policy, and case data.
2. Do NOT use external knowledge or make unsupported assumptions.
3. Output sections: Subjects & Accounts | Transaction Details | Suspicious Indicators | Historical Alerts.
4. Include [Source: ...] reference for each material claim.
5. If data is missing, write "Not available".
6. Use neutral, factual language. Do NOT accuse the customer.
7. Do NOT recommend case closure or STR filing — human analyst must decide.
8. Flag confidence as HIGH / MEDIUM / LOW for each section.

Additional prompt types: Entity extraction prompt, Case-note drafting prompt, Policy retrieval query template, Counterparty risk assessment prompt.

Risk Assessment

Key risks introduced by GenAI in AML investigations

AML is a regulated, high-stakes workflow. GenAI introduces new risk categories that require explicit governance.

Hallucination

Model invents transactions, entity links, or policy rules that do not exist in the evidence base.

Prompt Injection

Malicious text embedded in case documents or inputs manipulates model behavior unexpectedly.

Data Leakage

Customer PII or confidential investigation techniques exposed to unauthorized systems or users.

Over-reliance

Analysts accept AI output without verification, reducing investigation quality and accountability.

Weak Auditability

Cannot reconstruct what the model generated versus what the analyst reviewed and changed.

Bias & Fairness

Model may over-flag certain geographies or customer demographics without evidentiary basis.

Conclusion & Recommendation

Deploy carefully as a human-reviewed AML copilot

Key Takeaways

  • Business value: Reduces repetitive evidence assembly and improves consistency of case documentation.
  • Technical design: RAG grounds the LLM in internal evidence; knowledge graph supports relationship discovery.
  • Risk awareness: Hallucination, data leakage, prompt injection, auditability, and over-reliance require explicit controls.
  • Regulatory alignment: Designed to support explainability and human accountability at every stage.
  • Practical feasibility: A narrow pilot with measurable KPIs is more credible than immediate enterprise-wide deployment.

Recommendation

Proceed with a phased pilot under strong governance, private deployment, full audit logging, and mandatory human approval.

Phase 1: Controlled Pilot

Test summarization, retrieval, entity extraction with limited users and cases.

Phase 2: Validation & Governance

Assess accuracy, edit rates, security findings, analyst feedback, regulator readiness.

Phase 3: Gradual Scale-up

Expand only if pilot demonstrates safety, usefulness, and auditability.

GenAI should support AML investigators — not replace them. Copilot, not autopilot.
