Appendix A | Prompt Examples

Prompt 1: Extract from transaction data

This prompt converts raw transaction records into AML entities and graph-ready relations.

Input & Objective

prompt_extract_from_transaction = f"""
Please extract anti-money laundering related entities and relations from the following financial Transaction Data:
{transaction_text}
"""
Entities
Customer, Account, Merchant, Transaction, RiskType, Amount
Relations
Belongs_To, Initiates, Receives, Transfers_To, Related_To_Merchant, Triggers_Risk
Required Fields
Each entity includes id, text, type. Each relation includes source, target, type, properties.

Suspicious Transaction Rules

  • Amount near RMB 50,000, specifically RMB 48,000–49,999, with structuring pattern → RiskType = Structuring.
  • Late-night transaction between 23:00–05:00 with high frequency → RiskType = Late-night abnormal.
  • Same account receives and sends funds within 24 hours → RiskType = Layering.
Account → Customer Customer → Transaction Transaction → Customer Account → Account Customer → Merchant Transaction → RiskType

Appendix A | Prompt Examples

Prompts 2–3: Extract from alerts and case notes

These prompts extend extraction from transaction-level facts to alert-level reasoning and historical case documentation.

Prompt 2

Extract from AML alert text

The alert extraction prompt identifies customers, accounts, suspicious transactions, risk categories, regulations, related cases, and reporting thresholds.

Entities
Customer, Account, Transaction, RiskType, Regulation, Case, Threshold, Alert
Relations
Triggers_Alert, Violates_Regulation, Related_To_Case, Reaches_Threshold, Recommend_SAR, Requires_Freeze
Special Rules
Single transaction ≥ RMB 50,000 triggers large transaction reporting. Multiple transactions near RMB 50,000 within 24 hours indicate structuring risk. Funds consolidated from multiple accounts and transferred out indicate layering.
Prompt 3

Extract from investigation case notes

The case-note prompt captures investigation structure, responsible parties, conclusions, regulator reporting, and links to past cases.

Entities
Case, SuspectedCustomer, SuspectedAccount, GangMember, Conclusion, Regulator, Investigator
Relations
Involved_In, Gang_Related, Has_Conclusion, Reported_To, Cited_Regulation, Links_To_Past_Case
Metadata
Conclusion type, risk level, case status, timestamp, evidence, and relation properties are required for auditability.

Appendix A | RAG-Enhanced Prompt

Prompt 4: RAG-enhanced comprehensive extraction

Combines retrieved compliance knowledge with input text to generate valid JSON entities, relations, and a risk summary.

Prompt Logic

  • Role: AI anti-money laundering assistant for financial institutions.
  • Input 1: Retrieved compliance knowledge from RAG context.
  • Input 2: Text to analyze.
  • Output: AML entities, financial relations, and one-sentence risk summary.
  • Strict constraint: output must be valid JSON.
RAG Context Input Text Entities Relations Summary
Entity Types: 8 AML Financial Entities

1. Customer — name, ID, phone number
2. Account — account number, type, balance
3. Transaction — amount, timestamp, channel
4. Merchant — merchant name, industry
5. Branch — branch name, city
6. Regulation — code, title, threshold
7. RiskType — money laundering, fraud, terrorist financing
8. Case — case number, status, conclusion

Relation Types: 8 Financial Relations

Belongs_To: Account → Customer
Transfers_To: Account → Account, with amount and timestamp
Triggers_Risk: Transaction → RiskType
Involved_In: Customer → Case
Cited_Regulation: Case → Regulation
Gang_Related: Customer → Customer
Related_To_Merchant: Customer → Merchant
Requires_Freeze: Alert → Account

Output: entities, relations, summary
Use RAG Knowledge Judgment must incorporate retrieved compliance context.
Threshold Rule Transaction amount ≥ RMB 50,000 marks large reporting threshold.
Structuring Rule Multiple transactions within 24 hours near RMB 50,000 indicate structuring.
JSON Constraint No relation below 0.6 confidence; output strictly valid JSON.
